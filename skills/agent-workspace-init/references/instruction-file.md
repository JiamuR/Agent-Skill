# 将配置写入 agent.md

## 写入前的明确确认

先展示**准确绝对路径、作用范围、写入方式及具体内容或可审阅差异**，再取得用户对本次写入的明确确认。“配置没问题”不等于“写入这个文件”。沉默、默认选中、超时和技能安装均不算确认。

用户已经看过具体方案并明确要求写入对应文件时直接执行，不重复问。确认后内容、目标或作用范围实质变化，只展示相关变化并重新确认，不重新询问全部配置。用户只要求增加写入能力或打包技能时，不修改实际指令文件。

- 用户指定 `agent.md` 时保留准确文件名；不能默默改成 `AGENTS.md`，两者也不是同名文件。若宿主要求其他入口，先核实再说明差异，由用户决定。
- 任务、项目、全局范围分开；项目规则不能写到全局位置。根目录中的文件不必然覆盖所有项目。
- 权限不足走正常审批；需要新目录仍先确认名称和用途。确认前只做对话或已授权交付目录内的预览。
- 拒绝或暂缓时记录决定，不写入，也不能改用记忆或其他指令文件绕过决定。

确认示例：“以下差异将合并到 E:\workBuddy_file\项目A\agent.md，仅供项目A使用，保留现有无关规则。是否确认写入？”

## 生成内容

用已确认的实际值形成能独立理解的指令，不复制整个技能或聊天记录。包括：Agent 和范围、项目根路径与新任务规则、两类系统目录的实际路径及保护边界、输出/工作/附件角色映射、C 盘限制和例外规则、附件校验及删除条件、迁移提醒与权限边界、已确认记忆策略及入口、待确认事项和变更规则。

未知路径不编造；未确认选项留在待定清单，不写成启用规则。记忆入口未知可写“使用前先确认宿主支持的入口，不自动写入”。未给容量配额不写数字；没有硬配额机制不声称系统限制已部署。

## 合并与防重复

1. 完整读取目标，记录操作前哈希；不可读时停止覆盖，不能当空文件。先按 [恢复流程](recovery.md) 留检查点。
2. 现有文件先备份到已确认工作目录，保留原名信息和时间标记。需要新备份目录先确认。目标不存在时记录“尚不存在”，防止后续并发新建被覆盖。
3. 新文件写简洁配置；已有文件保留无关内容，先检查全文有无重复或冲突，再决定合并位置。推荐使用唯一管理区块：`<!-- agent-workspace-init:begin -->` 与 `<!-- agent-workspace-init:end -->`。
4. 标记各一个且顺序正确时，只更新已授权区块。两者均不存在时，检查冲突后按批准方案插入一个区块；仅一端、重复、顺序错误时保留原文件，修复预览经确认后再处理，不盲改全文。
5. 旧冲突已获明确替换授权则修订；其他冲突列旧值、新值及影响供确认。不能靠末尾追加相反规则来“覆盖”旧规则。
6. 写入前重新读取或比对哈希。文件已变化、此前不存在的文件被别人新建时，重做差异与合并；实质超出原确认部分再问。核对后到实际写入仍可能发生竞争，应尽量使用宿主支持的安全替换方式；不宣称跨进程原子性已经得到保证。
7. 若目标已经与批准内容一致，验证后记录“无需变更”，不重复追加区块。写入结果未知时先对账，不重跑覆盖。

## 写入后检查

回读并核对批准内容、作用范围、实际路径与角色映射；有效内容不得有占位符、旧 Agent 名或未确认选项。核对管理区块唯一、区块外无关内容保留、没有互相冲突的规则。保存结果哈希、差异摘要及备份位置。

回告“已写入”“已验证”，只有得到宿主加载证据才说“已加载/已生效”。不因文件名就承诺自动加载，不擅自重启、安装插件或改加载配置。用户要求预览或暂未具备执行条件时交付草稿并说明阻碍；目标明确且授权和权限均满足时，完成实际写入及验证。
