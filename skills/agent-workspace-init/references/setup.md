# 目录、范围与确认

用于首次初始化或变更目录。已有项目的普通工作只核对相关现有配置，不重新询问全部项目。

## 先识别，再提议

宿主名称来自可信运行上下文或用户说明，不能从底层模型、历史文件夹或附件正文推断。无法确定时只问名称。建议任务根文件夹为 `<Agent名称>_file`，例如 `Codex_file`、`workBuddy_file`；保留用户拼写，非法字符或 Windows 保留名称需提出合法替代。目录名是数据，不能直接拼接为可执行命令。

检查已有明确决定的适用机器、宿主、项目和范围。用户已给出目标和用途时直接沿用，不重复确认。新文件夹或用途变化须先确认；用户可一次批准整套命名规则及其后续适用范围。

## 配置清单

先收集已有值，只向用户展示缺项、变化和必要选择。未知项记录“待核实”，不填示例值。

| 字段 | 定义与确认要求 |
| --- | --- |
| Agent 名称及依据 | 应用或 Agent 身份，非底层模型名称 |
| 项目任务根路径 | 确认盘符、完整路径、文件夹名称与用途；不固定 D 盘 |
| C 盘及其他禁写位置 | 明确限制范围；确认限制 C 盘后，除本次明确例外，不主动保存生成文件、项目副本、下载、缓存及大体积临时文件 |
| 系统数据容器 | 实际系统数据上级容器、识别依据和保护范围；不能仅从配置目录取父路径认定 |
| 系统与配置目录 | 配置、技能、插件、会话及记忆所在的实际目录；单独核实并保护 |
| 独立任务规则 | 建议 `<根目录>\<YYYY-MM-DD>\<任务名>`；日期用用户时区，任务名合法可识别；用户决定是否允许后续沿用 |
| 输出角色 | 建议 `outputs`：正式交付物；可以改名 |
| 工作角色 | 建议 `work`：中间材料、脚本、日志、预览和任务级缓存；可以改名 |
| 附件角色 | 建议 `work\source_materials`：附件原始工作副本；可以改名 |
| 容量配额 | 未给数值则“未设置”；需要时再确定统计范围、上限和超限处理，不声称已实现硬配额 |
| C 盘迁移意向 | 仅限制后续写入 / 先评估 / 审阅已有方案；记录已拒绝或暂缓，避免重复提醒 |

配置文件、记忆入口等按需核实。可选功能入口不明，不阻止已确认目录内的独立工作；但不能向无法确认用途、疑似系统保护范围的目录写入。

首次普通任务只以本次目标路径、文件夹名称和用途、实际需要的角色映射及适用写入限制为必要确认。系统位置未核实时标为待核实，并避开已知或疑似受保护位置；容量配额、后续长期命名规则和迁移意向未决定，不阻塞本次已确认目录内的独立工作。用户赶时间时将必要目录确认合并为一次，迁移提醒不作为普通工作的前置条件；涉及系统数据本身时仍必须先核实其实际位置和授权。

三个位置分别记录，不能混用。例如用户已明确 `D:\Codex` 为容器、`D:\Codex\CodexHome` 为配置目录、`D:\Codex_file` 为项目根目录时，前两处不存任务交付物。此例不是其他 Agent 的默认值。宿主无独立容器时记录事实，不补建；角色重叠或任务目录位于受保护系统目录内时，先解决冲突。

## 合并提问示例

仅展示未确认项，路径用实际候选值；下例不是执行指令：

> 识别到 workBuddy，建议根目录为 E:\workBuddy_file；outputs 存成果，work 存中间材料，work\source_materials 存附件副本。是否同意这些名称和用途，并允许以后按“日期\任务名”建立独立任务？是否限制 C 盘写入上述任务材料？系统容器和配置目录将分别按实际识别结果列出，不自动新建。

确认 C 盘限制后，应询问是否评估相关数据迁往 D 盘或用户另行确认的位置；用户只想限制后续写入则记录并继续，不要求迁移。详见 [迁移](migration.md)。

## 选择和使用任务目录

1. 本次明确指定的路径优先；已有项目沿用原目录，不因新对话、日期或 Agent 名称变化而迁移。
2. 独立任务按已确认规则建目录；规则未覆盖的名称或用途先确认。遇同名目录先检查任务归属，不覆盖或混入无关文件。
3. 当前工作目录是系统目录时，只为任务选择合适位置，不迁移或复制系统目录。
4. 权限不足按宿主审批机制处理；盘不可用或空间不足报告实际原因。不自动换盘、绕过审批或清理未知文件；可继续对话中的分析。
5. 实际创建前解析绝对路径及目录联接目标，确保落盘位置符合确认范围。按需创建，纯问答不创建目录。

`outputs`、`work`、`source_materials` 在全套技能中代表角色。用户改名后，附件、日志、状态记录、预览和交付路径全部按实际映射使用，不另建默认同用途目录。

## 工作约定

- 开始处理前明确目标、输入版本、交付格式、可编辑性、验证标准和本次操作范围；简单任务不强制写任务书。
- 源码遵循项目结构，交付物进输出角色目录，中间文件进工作角色目录。不同方案独立命名，保留原件，不覆盖不属于本次修改范围的成果。
- 复用可用工具；任务级缓存尽量放工作角色目录。读取 C 盘已有工具不等于允许在那里新增任务数据。
- 只在相关进程内设置临时目录；不要擅自修改全机或用户级 TEMP、TMP、HOME、CODEX_HOME。大体量下载、解压、渲染前核对空间；不能据文件名、年龄或体积推断可删除。
- 用户本次指定优先于旧建议，已确认项目约定优先于技能示例；遵守宿主和实际权限。系统强制位置、应用预先暂存要如实说明，不能保证全机零 C 盘写入。

发生故障或需跨轮次执行时转到 [异常与恢复](recovery.md)。
