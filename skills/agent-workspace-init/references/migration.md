# C 盘数据迁移

只有本轮涉及迁移意向、盘点或执行时读取。技能的可用性不代表获得迁移授权，也不要求用户必须迁移。

## 提醒与评估

确认限制 C 盘后，主动提醒是否评估当前 Agent 的相关可迁移数据，目标可为 D 盘或用户另行确认的位置。已有“仅限制后续写入”“暂不迁移”或已完成的决定时沿用，不每轮重问；有新相关数据或新请求再评估。

可问：“已确认限制 C 盘。是否先评估当前 Agent 在 C 盘的相关数据，判断哪些可迁移？也可以只限制以后写入。具体源路径、目标和操作方案会另供你确认。”

同意评估只允许相关范围内的只读盘点。记录来源、用途、大小、是否使用中、宿主支持方式和未知项；不能盘点并清理整个 C 盘，不能把看起来像缓存的文件直接认定可迁移。

## 三类目标分开安排

| 类型 | 目标原则 |
| --- | --- |
| 运行时、依赖、可迁移缓存 | 核实支持方式后，可放用户确认的系统数据容器下按用途划分的子目录 |
| 配置、技能、插件、会话、记忆 | 宿主明确支持迁移时使用已确认的系统与配置目录；核对目标已有内容，不能整体覆盖 |
| 项目、交付物、附件、中间材料 | 进入已确认的项目任务根目录及对应角色目录，不进入系统目录 |
| 应用程序、活动数据库、未知缓存、系统文件 | 先核实受支持的迁移/重配置方式；不拖动安装目录、不盲拷活动数据库、不混入全机 TEMP/TMP 迁移 |

`D:\Codex`、`D:\Codex\CodexHome`、`D:\Codex_file` 是上述不同角色的用户示例，不是任意机器的默认值或现成授权；其他 Agent 不能机械改写系统路径。D 盘不可用、空间不足或无权限时报告阻碍，不自行换盘。目标新文件夹名称、用途须已确认。

## 方案到执行

1. **方案：**逐项列实际源/目标路径、类型、大小、迁移依据、复制或重建方式、配置变更、停用/重启影响、目标冲突、验证及回退步骤。原件未删除前不能把预计释放空间当作实际节省。
2. **确认：**用户审阅具体方案后明确同意才执行。限制 C 盘、同意评估、确认迁移、删除原件是不同事项；完整方案可一次明确覆盖，但不能推断扩展。权限仍按宿主机制处理。
3. **检查点：**按 [恢复流程](recovery.md) 记录操作前状态、备份、确认范围和预期变化。明确需要关闭程序时按方案处理，不擅自终止无关应用。
4. **复制与切换：**优先复制并校验，再按支持方式切换。保留可恢复原状态；目标非空不整目录覆盖，未知冲突先暂停相关项。
5. **验证：**核对文件清单、数量、大小；配置、会话、记忆等重要数据校验 SHA-256。重建缓存按功能和可重建性验证，不假称哈希一致。用新进程实际读写路径、启动和代表性功能证据证明切换；只修改变量、注册表或配置不算完成。
6. **清理或保留：**验证失败按已确认回退方案处理；成功后也仅在明确授权覆盖具体原件时删除。核实实际路径、联接目标和副本仍有效，删除后复核源不存在及实际释放空间。未授权清理则保留并报告。

状态分别记录：待评估、方案待确认、已复制、已切换待验证、已切换并验证、原件待清理/已清理。中断时先对账，不能跳过实际切换验证直接删除 C 盘原件。

迁移结果若需保存到指令文件或长期记忆，分别按 [指令写入](instruction-file.md) 和 [记忆写入](memory-decisions.md) 的授权执行，不自动双写。全机 TEMP/TMP 等存储调整必须单独评估和明确授权。
