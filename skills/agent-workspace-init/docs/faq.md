# 常见问题与错误用法

涉及用户决定的问题，按“直接解释 → 建议及理由 → 可选操作与影响”说明。以下是话术示例，Agent 应结合实际路径、文件和已确认范围给出具体选项；阅读或复制这些文字不代表用户已选择。推荐选项不自动执行，已有明确决定无需重复询问。纯解释性问题直接答清楚，不额外要求确认。

## 1. 为什么没有自动选 D 盘？

盘符由用户确认，D 盘是常见示例，不是所有机器的默认值。已有明确的 D 盘配置继续沿用，不会每次再问。

**建议：**优先沿用已明确且可用的目录；首次配置时先检查候选盘是否存在、空间是否够用，再提出实际完整路径，避免选到不可用位置。

**需要选择时：**A. 使用已核实的建议路径；B. 指定另一个具体位置；C. 暂不创建，先看方案。用户指定新路径后，仍需核对用途和权限。

## 2. workBuddy 为什么不能直接使用 CodexHome？

任务根文件夹可按宿主建议为 `workBuddy_file`，但系统目录和记忆入口取决于真实安装配置。不能把 `CodexHome` 文本替换后当作有效路径，也不能把新 Agent 的数据混入已有 Codex 配置。

**建议：**沿用 workBuddy 自身真实配置，任务目录单独确认，以免影响其他 Agent。确需变更时可选：A. 保持现有系统位置；B. 只读核实当前位置和迁移支持；C. 暂缓处理。B 不包含实际迁移授权。

## 3. 系统容器、系统配置目录和项目目录有什么区别？

容器承载相关系统数据；配置目录保存配置、技能、会话或记忆；项目目录放任务和成果。用户给出的 Codex 示例是 `D:\Codex`、`D:\Codex\CodexHome`、`D:\Codex_file`。前两者受到保护，不能当作报告或任务根目录。

**建议：**用“实际路径、用途、保护范围”分别列出三类位置。只是理解概念时无需确认；尚未配置时，用户可选：A. 确认实际识别的三类位置；B. 更正某一位置；C. 未核实部分保持待定，仅继续不受影响的任务。

## 4. 每个文件夹都要再问一遍吗？

你可以一次批准名称、用途和以后适用的命名规则。规则覆盖的目录按需创建，不重复确认；新增用途、改盘符或超出已批准范围时才问。创建普通文件不等于新建一种目录配置。

**建议：**工作方式稳定时，一次确认清楚后续适用范围，减少重复提问。可选：A. 确认这套规则并允许后续沿用；B. 仅确认本次任务；C. 修改名称或用途后再确认。A 不等于允许写入全局指令或记忆。

## 5. 限制 C 盘后，能保证完全不占用 C 盘吗？

不能。技能约束 Agent 可控制的操作；应用接手前的剪贴板暂存、系统强制路径和其他程序写入不受此文本控制。你可先把文件保存到项目工作目录再上传，但宿主仍可能产生自己的副本。

**建议：**先限制后续可控制的任务写入，再根据实际占用决定是否评估迁移，避免为了少量暂存直接修改全机设置。可选：A. 只限制以后写入；B. 先评估当前 Agent 相关数据的迁移；C. 暂缓迁移决定。B 仅为只读评估，迁移和清理须审阅具体方案。

## 6. 文件已经复制，为什么还不能删原件？

复制存在不证明内容完整。所有副本至少核对大小；不可重获材料、正式分析依据和准备删除源文件的附件还须核对 SHA-256。通过校验后，也需明确授权删除具体原件，并复核删除结果。

**建议：**必要校验完成前保留原件，保障材料可恢复。校验未通过时只能继续排查或暂缓，不能提供“跳过校验删除”选项。

**校验通过后可选：**A. 保留具体原件；B. 确认删除已展示清单中的原件；C. 稍后决定。B 必须先列明实际源路径、副本路径与校验结果，只覆盖这份清单。

## 7. “配置没问题”是不是等于同意写入 agent.md？

不是。写入前需要你审阅准确目标、范围和内容，并明确同意本次写入。你已经对这份具体方案说“确认写入”时不会重复问；之后实质变化只确认变化部分。

**建议：**先看准确目标、作用范围及变更内容，避免把项目规则写成全局规则。展示后可选：A. 确认将这份内容写入该文件；B. 修改指定内容后再确认；C. 只保留预览，暂不写入。推荐哪个选项取决于用户本次目标，不能一律推荐写入。

## 8. agent.md 与 AGENTS.md 可以自动互换吗？

不能。文件名和宿主加载机制应分别核实。技能保留你指定的名字；即使成功保存，也只报告“已写入”，有实际加载证据才报告生效。

**建议：**先核实应用实际读取的文件名和位置。如果与指定名称不同，说明差异后可选：A. 采用已核实的宿主入口；B. 保留原指定名称，仅作为配置资料保存；C. 暂不写入。A 如涉及新目标或范围，还需展示准确内容并确认写入。

## 9. 状态记录是不是长期记忆？

不是。工作目录中的任务状态用于恢复当前任务。长期记忆另需明确请求、支持的宿主入口和实际权限。状态文件中的“已确认”还需可核实来源，不能靠文件文字自行授予权限。

**建议：**进度只存任务记录，确实需要以后复用的稳定偏好才提出长期保存。可选：A. 仅作本任务记录；B. 审阅具体偏好、适用范围和入口后确认保存为记忆；C. 修改候选内容。不能将整份任务日志默认转为长期记忆。

## 10. 中断后需要从头确认吗？

不用重问有可靠依据的原决定。Agent 会核对任务状态及真实文件，跳过已完成步骤，仅补问变化或缺失项。若日志还写“执行中”但文件已经写好，先验证现状，不重复追加。状态损坏时保留文件并重建能证实的部分，不盲目重做。

**建议：**有可靠依据且仍在授权范围内时，核实后直接继续，并讲清从哪一步恢复，无需再次确认。只有确实存在不同处理方向时才提供选项，例如：A. 沿用可核实的原方案；B. 修改发生变化的部分；C. 暂停后续操作。授权无法核实的高影响操作，必须先补齐该项确认。

## 11. C 盘迁移是不是把所有数据移到同一个目录？

不是。运行时、配置和任务文件分开安排。先评估，再审阅源路径、目标、影响、验证及回退方案；应用已实际切换后才考虑获授权的原件清理。只改一个环境变量不能证明迁移完成。

**建议：**先做分类盘点，保留可以回退的原件。方案尚未形成时可选“只评估”或“暂缓”；具体方案已展示后可选：A. 确认方案中的复制与切换，暂不清理；B. 修改范围或目标后再确认；C. 暂不迁移。原件清理须明确列出对象与验证前提，不能隐藏在“全部迁移”一项里。

## 12. 报错会自动改存 C 盘或自动清缓存吗？

不会。统一提示会告诉你哪里受阻、已知原因、影响和下一步。无权限申请必要权限，空间不足说明空间问题；不会自行更换盘符或删除未知文件。

**建议：**优先解决已确认位置的实际阻碍；权限问题按宿主审批处理，不额外重复询问同一授权。确需用户决定替代办法时，可选：A. 暂保留对话结果，解决原位置问题后保存；B. 审阅并确认新的完整目标路径；C. 暂停相关写入。不要将“先出结果”理解为允许换盘。

## 常见错误速查

| 错误用法 | 正确处理 |
| --- | --- |
| 把案例里的 E 盘路径直接当作已批准值 | 用当前用户确认的实际路径替换 |
| 认为安装技能就等于同意迁移和写入全局配置 | 逐项确认具体操作范围 |
| 只复制 SKILL.md，遗漏 references 文件夹 | 保留完整技能目录及相对路径 |
| 同名文件一律覆盖 | 核对任务归属与内容，必要时保留不同名称 |
| 校验失败但为节省空间先删源 | 保留源文件，排查后重新校验 |
| 命令超时后立即重跑删除或覆盖 | 先核实真实状态与文件身份 |
| 同意迁移就等于同意删除所有旧数据 | 以明确覆盖具体对象的清理授权为准 |
| 宿主没确认加载，却说全局生效 | 只报告已经证明的保存或提交结果 |
