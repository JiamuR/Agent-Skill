# 使用指南

## 直接复制这句话使用

> 使用「Agent初始化配置skill」，帮我检查并确认工作目录、文件夹用途和 C 盘限制。已有配置请沿用，缺失或需要修改的事项逐项问我；先说明方案，执行中讲清原因和进度，涉及迁移、删除、写入记忆或 agent.md 时，先取得我对具体操作的确认。

这个技能帮助你确认 Agent 的工作目录、C 盘限制、附件处理和配置保存方式。它不会因为被打开或导入就自动迁移数据、清理 C 盘或改写你的全局配置。

## 第一次使用

如果宿主支持技能导入，按该宿主的方式导入或选择 `agent-workspace-init` 文件夹；保留其中的 `SKILL.md` 和所有相对路径，不只上传入口一页。显示名称为“Agent初始化配置skill”；内部标识为 `agent-workspace-init`。

不支持技能导入时，可把完整文件夹作为可访问资料，并明确要求 Agent 先读 `SKILL.md`、按路由读取相关参考文件。不同宿主是否自动识别技能、如何加载指令文件，需要以实际能力为准。

确认 Agent 能访问完整技能目录后，发送本页顶部话术。只有技能名称、截图或尚未可读取的压缩包，不足以证明技能已加载；Agent 无法读取时，应说明需要提供哪些文件，不假称已启用。

支持显式调用语法的宿主可发送：

> $agent-workspace-init 帮我确认初始化配置，先展示方案，不做迁移、不写入全局指令。

## 怎么生效

1. **读取技能：**当前应用导入或让 Agent 读取完整技能文件，Agent 才能按其中规则处理本轮任务；自然语言是否自动触发由应用决定。
2. **确认并执行：**Agent 核对已有配置，把待定项说明白；你确认具体目录或操作后，再在实际权限允许的范围内执行、校验并报告进度。批准技能使用不等于批准全部迁移和清理。
3. **后续继续使用：**若需跨对话保存规则，另行审阅并确认写入受支持的指令文件或记忆入口。只有实际加载或采纳证据充分，才说相关范围已生效；不能因为保存了 agent.md 就保证以后所有对话自动遵守。

简短实例：第一次使用时确认目录后创建；已经配置好的电脑只查缺项；上传图片时按已确认目录复制并校验。三个场景都应说明当前在做什么，具体原件删除另按授权处理。

## 按需求选择一句话

| 你的目标 | 可直接复制的请求 | 预期行为 |
| --- | --- | --- |
| 首次配置 | 使用这个技能确认 Agent 名称、任务根目录、目录用途和 C 盘限制 | 提出具体方案，确认后按范围设置 |
| 已有配置 | 我的目录已经配好了，只检查有没有缺项 | 核对相关约定，不重建、不迁移 |
| 只处理图片 | 按已确认的附件目录接手这张图片，保留暂存原件 | 复制与校验，不触发全套迁移 |
| 调整目录 | 将以后独立任务的正式交付目录名称改为“成果”，先说明影响 | 只审阅该变更，保留其他映射 |
| 保存到指令文件 | 把这些已确认配置整理成 agent.md 预览，告诉我路径和范围，先别写入目标文件 | 生成可审阅内容，等待明确写入确认 |
| 记住偏好 | 请将这条已确认偏好保存为本项目记忆：…… | 核实宿主入口，按项目范围保存并报告结果 |
| 评估 C 盘数据 | 只评估当前 Agent 在 C 盘的相关可迁移数据，给我源路径、目标和方案 | 只读盘点，不搬动、不清理 |
| 继续上次任务 | 继续上次初始化，先读取任务状态并核对实际文件，只问变化或缺失项 | 先对账，再从未完成步骤继续 |

## 通常会经历什么

1. Agent 核对已有决定，向你展示未确认的目录和用途。你可一次确认整套规则，也可只确认本次任务。
2. 你确认 C 盘限制后，Agent 提醒是否需要迁移评估；选择“不迁移”不影响正常使用。
3. Agent 按授权处理文件，并报告实际校验结果。有阻碍时说明位置、原因、影响及下一步。
4. 如需写入 `agent.md`，先审阅准确路径、作用范围和内容，再明确说“确认写入上述文件”。只说“配置正确”不会写入。
5. 最终得到配置摘要、实际文件链接和必要的待确认事项。多步任务会按需在已确认工作目录保存状态，方便下次核对恢复。

## 不需要用它的情况

普通问答、翻译、与存储约定无关的文档措辞修改，不必启动初始化。创建或打包本技能的请求，只生成技能交付物，不会自动把其中示例应用到当前电脑。

遇到概念不清，查 [FAQ](faq.md)；想看完整对话，查 [案例](examples.md)。
