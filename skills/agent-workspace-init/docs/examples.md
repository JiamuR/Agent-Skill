# 完整使用案例

以下均为说明性对话，**不是当前电脑的实际状态、授权或执行证据**。路径、哈希和结果需以真实任务重新核实；不能把示例成功当作工具成功。

入口处仍保留简短使用示例；这里展示完整沟通过程。实际执行时沿用已有确认，只在确有选择或缺少授权时展示适用选项，不把案例中的所有提问机械重复一遍。

## 案例一：首次配置 workBuddy，用户暂不迁移

**用户：**“使用初始化技能，想把任务放 E 盘，不想再占 C 盘。帮我先出方案。”

**Agent：**读取宿主提供的身份与当前目录，确认是 workBuddy。提出：

| 项目 | 方案 |
| --- | --- |
| 任务根目录 | E:\workBuddy_file |
| 独立任务 | 根目录下按用户时区使用 YYYY-MM-DD\任务名 |
| 成果 | outputs |
| 中间材料 | work |
| 附件副本 | work\source_materials |
| C 盘限制 | 任务文件、下载、缓存及大体积临时文件不用 C 盘；本次明确例外另行处理 |
| 系统容器、配置目录 | 按宿主实际识别结果分别展示；暂不可识别时标为待核实，不填猜测路径 |

**建议及原因：**“建议采用上表中的任务目录名称和用途，并先限制以后写入。这样能明确新文件的存放位置，也不需要现在改动尚未核实的系统数据。E 盘是否可用、目录是否可写需要实际检查；若不满足条件，我会说明原因，不自动改用 C 盘。”

**用户确定选项：**“对于上表的目录规则，你可以选 A：确认后供后续独立任务沿用；B：只用于本次任务；C：修改指定名称或用途后再确认。这里的沿用不包含写入长期记忆或指令文件的授权。对于 C 盘已有数据，你可以选择先不迁移、另做只读迁移评估，或暂缓决定；迁移评估不等于执行迁移。”

**用户：**“确认并允许以后按这个规则建任务。只限制以后写入，暂不迁移。先做本次资料整理。”

**Agent 的动作：**记录上述范围，核实本次任务路径不属于受保护系统位置、权限满足后按需创建相应目录；不为本轮无关的未识别系统功能建目录。只创建实际需要的角色目录，不迁移 C 盘数据。多步任务在工作目录记录检查点。

**交付示例：**“已确认 E:\workBuddy_file 及三类子目录规则，已创建本次整理所需目录并验证可访问。C 盘迁移暂缓；系统目录若后续涉及修改，再核实实际位置。尚未写入指令文件或长期记忆。”

**下一步：**按上述规则继续本次资料整理。若希望后续新对话也采用规则，再单独审阅宿主支持的保存入口和拟写入内容；当前对话中的确认不证明跨对话已生效。

**用户接着说：**“把已确认规则整理成 agent.md 预览，作用范围是本项目。”

**Agent：**读取指定项目现有文件并展示拟写入路径、范围和差异。用户只说“配置没问题”时保持预览；用户随后明确“确认将以上内容写入这个项目的 agent.md”后，备份已有文件、核对未被修改、合并批准内容并回读验证。

**写入前的建议及选项：**“你目前要求预览，我建议先核对具体路径、作用范围和差异，再决定保存。你可以选 A：确认向展示的准确路径写入以上内容；B：修改内容后再确认；C：仅保留预览。选择 A 也不授权迁移、清理或另写长期记忆。”不假设名为 agent.md 的文件一定被宿主自动读取。

**交付示例：**“已写入指定项目 agent.md，回读与批准内容一致，无关规则保留；宿主是否自动加载尚未验证。”

## 案例二：附件同名，校验失败后恢复

**前提：**项目和附件角色目录已明确确认。收到 `C:\Temp\clipboard.png`，目标已有不同内容的同名图片；用户说“分析这张图片，原件先保留”。

**Agent 的动作：**使用不冲突名称复制为项目附件目录中的 `clipboard_02.png`，保留旧图片；记录源与目标。材料是正式分析依据，因此核对大小及 SHA-256。

**假设出现故障：**两边大小相同但哈希不同。Agent 不将副本用于可靠结论，按统一格式报告：

```text
状态：受阻｜校验不一致
发生位置：clipboard.png 复制后的 SHA-256 校验
原因说明与依据：大小一致、源与副本哈希不同，尚不能确认副本与原件一致；具体原因尚未确认
当前影响：源文件和旧图片均保留，新副本暂不作为可靠输入
下一步：检查源是否在复制时变化，稳定后重新复制并核对；无需重新确认目录
```

源稳定后，用不覆盖旧材料的方式重新复制并核对；成功才进行分析。记录实际计算的哈希，不把本案例当作哈希证据。用户未授权删除源，因此保留 C 盘原件并回告。

**建议及原因：**“建议先检查源文件是否仍在变化，再重新复制并校验。大小相同只能说明字节数相同，哈希不同意味着当前副本尚不能确认与原件一致，因此不能拿它作为可靠分析输入。”

**适用选项：**原有分析授权内可完成的检查和重试直接继续，反馈进度，不重复请求同意；若源持续变化而需要用户选择，则提供 A：用户保存稳定版本后继续（推荐）；B：改用用户指定的另一份已核实材料，说明结果仅适用于该材料；C：暂停该附件分析。不得提供跳过校验并删除原件的选项。

**结果与下一步示例：**“重新复制的副本已通过大小和 SHA-256 校验，接下来用该副本分析；旧图片和 C 盘原件均保留。”仅在真实校验成功后使用这句话；仍失败时报告失败证据和待解决事项。

如果 Agent 在复制后中断，恢复时先检查已有副本。副本已经有效则继续分析；无须再复制一份或让用户重新确认全部目录。

## 案例三：agent.md 已写入，但确认回执前中断

**前提：**用户已审阅项目范围、准确路径和差异，并明确批准写入。操作前状态记录有原文件哈希、备份位置、批准内容及可信对话依据；日志停在“执行中”。

**用户：**“继续刚才的配置保存。”

**Agent 的动作：**读取状态及可信确认依据，重新读取实际目标文件。目标已经完整符合批准内容，且管理区块只有一处、无关内容保留时，记录“已验证”，不再次追加，不要求用户重批同一内容。

**交付示例：**“已核实上次写入实际完成，本次只补齐回读验证和任务记录；未重复修改文件。加载效果尚未验证。”

若文件与批准内容不同，先区分上次未写完还是其他程序新修改；保留现状、重新生成差异，只有超出原确认的部分才再次征求决定。

**建议及原因：**“建议先核实文件实际内容，而不是看到日志停在执行中就重新写入；上次操作可能已经成功，重复追加会造成规则重复。”

**适用选项：**文件符合可信批准内容时直接补齐验证，无需用户重复确认。若发现新的冲突，则展示具体差异并建议先保留现状，提供 A：保留现状，仅输出冲突说明（推荐）；B：审阅新的合并内容后明确批准写入；C：暂停处理。原审批不能覆盖其他程序新增的内容或新的修改范围。

**下一步：**有可靠加载证据时核实宿主是否采用规则；缺少证据就标为“文件已保存，加载效果未验证”，不声称已跨对话生效。

## 案例四：迁移复制完成，不代表可以删除 C 盘

**用户：**“已限制 C 盘，先评估这个 Agent 有哪些相关数据能放 D 盘。”

**Agent：**只读盘点相关目录，提出分为系统容器、配置目录和项目目录的方案，列来源、大小、支持依据、停用影响、切换验证和回退；用户审阅后只批准复制与切换，未批准清理。

**建议及原因：**“建议先完成只读评估，明确哪些目录支持迁移、应用怎样使用新位置及失败怎样回退。D:\Codex 或 D:\Codex\CodexHome 只是 Codex 场景中可能采用的目标，必须确认实际用途、宿主支持和现有内容；不能套用于其他 Agent，也不能覆盖受保护目录。”

**用户确定选项：**评估方案明确后，展示准确源路径、目标路径、操作范围和影响，提供 A：批准方案中列明的复制与切换，保留原件（满足迁移条件时推荐）；B：调整目标或范围后重新审阅；C：仅保留评估结果，不执行迁移。缺少支持依据或条件不满足时，建议补齐评估或暂缓，不推荐直接迁移。无论选择哪项，都不自动包含清理原件的授权。

**假设中断点：**文件已复制到 D 盘，但新进程仍使用 C 盘配置。

**恢复动作：**标为“已复制、切换未验证”，保留原件；核对支持的配置方式和进程状态，按原确认范围完成或修复切换。若需新增重启、其他配置变更或不同目标，先确认新增影响。

**交付示例：**“复制已核验，但应用尚未使用新位置，迁移未完成；C 盘原件保留，未释放该部分空间。”

只有应用实际读写新位置且功能验证通过，才报告已切换；清理仍取决于明确覆盖原件的授权。

**下一步与可选操作：**按已批准范围核实或修复切换，并说明已完成、正在做和剩余步骤。若需要新增操作，先展示原因和影响，供用户选择批准具体新增操作、修改方案或暂停并保留两边数据。只有切换和功能验证完成后，才另行展示可清理的准确原件列表、校验依据和回退影响，让用户选择保留、明确授权删除列明原件或以后再决定；删除后复核原路径不存在，才报告清理结果。
